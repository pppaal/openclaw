# 03. 가격과 수익 계산 (대략 추정)

> **중요:** 아래 숫자는 전부 **거친 추정치**입니다. 약속이나 보장이 아닙니다.
> 실제 API 단가, 손님 문의량, 답변 길이에 따라 크게 달라집니다. 첫 고객 한두 곳 운영해서 **진짜 숫자**를 잡은 뒤 가격을 확정하세요.

---

## 1. 추천 가격 (설치비 + 월 구독)

가게당 **1회 설치비 + 월 구독료** 구조. 두 가지 티어로 시작하세요.

| 티어 | 설치비(1회) | 월 구독료 | 포함 내용 | 적합 |
|---|---|---|---|---|
| **베이직** | 5만 원 | **3만 원/월** | FAQ 자동응대(가격·시간·예약·주차 등), 월 문의 한도 ~500건 | 작은 가게, 가격 민감 |
| **스탠다드** | 10만 원 | **5만 원/월** | 베이직 + 예약 문의 정리 전달, 문구 맞춤, 월 한도 ~1,500건 | 문의 많은 학원·미용실 |

가격 원칙:
- **설치비를 받는 이유:** 초기 셋업(가게 정보 입력·말투 조정·테스트)에 당신의 시간이 들어갑니다. 공짜로 하면 지칩니다.
- **월 구독료는 ROI로 설득.** 학원이면 "등록 1건이 곧 본전". 미용실이면 "노쇼·놓친 예약 한 건이 곧 본전".
- 1호 고객은 02 파일대로 무료/반값. **2호부터는 정가.**

---

## 2. 솔직한 원가 분석 (가게 1곳, 월 기준)

### (a) Claude API 비용 — 가장 중요
손님 메시지 1건마다 비용이 듭니다. 핵심은 **메시지당 토큰(글자) 양**입니다.

대략적인 개념(추정):
- 손님 질문 1건 + 봇 답변 1건 = 입력·출력 합쳐 대략 수백~1,000여 토큰.
- 거기에 **시스템 프롬프트(가게 정보·말투 지침)**가 매 호출마다 같이 들어갑니다. 이게 의외로 큽니다.
- 작은 모델(예: Haiku급)을 쓰면 메시지 1건당 대략 **수 원~수십 원** 수준으로 잡힙니다. (정확치 아님 — 직접 측정 필요)

월 추정:
| 월 문의량 | 메시지당 비용(가정) | 월 API 비용(추정) |
|---|---|---|
| 300건 | 약 10원 | 약 3,000원 |
| 500건 | 약 10원 | 약 5,000원 |
| 1,500건 | 약 10원 | 약 15,000원 |

> 위 "메시지당 10원"은 **설명용 가정치**입니다. 모델·답변 길이에 따라 5원이 될 수도, 50원이 될 수도 있습니다. **첫 고객에서 실측하세요.**

### (b) 서버/호스팅비
- 카카오 연동 웹훅을 받을 작은 서버 1대로 **여러 가게를 동시에** 처리할 수 있습니다.
- 소형 클라우드 인스턴스 또는 서버리스: 월 **5,000원~3만 원** 수준(전체 합계, 가게 수로 나눠짐).
- 가게가 늘수록 가게당 호스팅 단가는 **내려갑니다.**

### (c) 가게 1곳 월 마진 (스탠다드 5만 원 기준, 추정)

| 항목 | 금액(추정) |
|---|---|
| 월 구독료(매출) | +50,000원 |
| API 비용(문의 500~1,500건) | -5,000 ~ -15,000원 |
| 호스팅 분담(가게당) | -1,000 ~ -3,000원 |
| **가게당 월 순익(대략)** | **약 32,000 ~ 44,000원** |

> 베이직 3만 원 티어도 문의량이 적으면 마진은 비슷하게 **2만 원대** 남습니다. 핵심: **문의 폭주하는 가게일수록 API 비용이 커지므로 한도/효율 관리가 중요**합니다(아래 4번).

## 3. 수익 시뮬레이션 (월 기준, 전부 추정)

스탠다드 5만 원/월 기준. 호스팅은 전체 합산. 설치비는 1회성이라 제외.

| 가게 수 | 월 매출 | API 비용(합) | 호스팅(합) | **월 순익(대략)** |
|---|---|---|---|---|
| **5곳** | 250,000원 | 약 50,000원 | 약 20,000원 | **약 180,000원** |
| **20곳** | 1,000,000원 | 약 200,000원 | 약 40,000원 | **약 760,000원** |
| **50곳** | 2,500,000원 | 약 500,000원 | 약 60,000원 | **약 1,940,000원** |

해석:
- **5곳**은 "용돈 + 검증" 단계. 이 단계에서 진짜 원가를 측정하세요.
- **20곳**이면 의미 있는 부수입(월 75만 원선). 이때 **자동화에 투자할 가치**가 생깁니다.
- **50곳**이면 월 순익 약 190만 원. 단, 혼자 50곳을 운영·영업하긴 빡셉니다 → 03~04 단계 자동화 필요.
- 설치비(곳당 5만~10만 원)는 **위 표에 안 들어간 추가 일시 수입**입니다. 가게 늘릴 때 현금 흐름에 도움.

> 다시 강조: 위 모든 숫자는 추정입니다. API 단가가 가정의 2배면 순익은 줄어듭니다. **그래서 마진 보호가 사업의 생존 문제입니다.**

---

## 4. 마진 지키는 법 (꼭 적용)

1. **작은 모델을 기본으로.** 단순 FAQ는 가벼운 모델(Haiku급)로 충분합니다. 비싼 모델은 어려운 질문에만.
2. **답변을 짧게.** 시스템 프롬프트에 "2~3문장으로 짧고 친절하게"를 넣으세요. 길수록 출력 토큰=돈입니다.
3. **시스템 프롬프트 다이어트 + 캐싱.** 매 호출에 들어가는 가게 정보가 길면 비쌉니다. 핵심만. 가능하면 프롬프트 캐싱으로 반복 부분 비용 절감.
4. **자주 묻는 질문은 AI 안 거치고 바로 답.** "영업시간?" 같은 건 규칙(정해진 답)으로 처리하면 그 건은 API 비용 0원입니다.
5. **가게별 월 메시지 한도 설정.** 티어별 한도(예: 베이직 500건)를 넘으면 안내 후 상위 티어 전환. 폭주하는 가게가 마진을 잡아먹는 걸 막습니다.
6. **API 사용량 알림·예산 한도(budget cap) 설정.** 콘솔에서 월 한도와 알림을 걸어, 예상 못 한 폭탄을 차단하세요.
7. **이상 트래픽 방어.** 한 손님이 봇과 무한 수다 떨면 비용입니다. 같은 사용자 분당/일일 메시지 상한을 두세요.

> 한 줄 요약: **싼 모델 + 짧은 답 + 규칙 처리 + 한도 설정.** 이 네 가지가 마진을 지킵니다.
